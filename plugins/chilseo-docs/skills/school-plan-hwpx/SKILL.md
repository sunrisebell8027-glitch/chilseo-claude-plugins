# 학교 계획서 → 한글(HWPX) 내부결재 양식

선생님이 쓴 계획서 원고를 학교 공용 양식의 `.hwpx`로 만든다. 한컴오피스가 없어도 만들 수 있다.
기본 양식은 칠서초등학교 내부결재용 양식(`templates/chilseo_plan_template.hwpx`)이다. 다른 학교도 자기 학교 양식으로 바꿔 쓸 수 있다.

이 스킬 폴더는 `${CLAUDE_SKILL_DIR}`다. 값이 채워지지 않는 환경(Claude 앱 등)에서는 이 SKILL.md가 있는 폴더를 쓴다. 아래에서 `$S`는 그 폴더다.

## 꼭 지킬 것

1. **지어내지 않는다.** 원고에 없는 값(예산 항목·인원·날짜·장소·공문 번호)은 채우지 않고 묻는다. 모르는 값은 "미정" 또는 "협의 예정"으로 쓰고 그렇게 알린다.
2. **질문은 만들기 전에 한 번에 모은다.** 모자란 값을 한 화면에 모아 묻고, 답을 받은 뒤 만든다.
3. **개인정보를 넣지 않는다.** 학생 이름·학번·연락처·상담·감정 응답 원문은 입력 JSON에도, 결과 문서에도 넣지 않는다. 명단이 필요한 붙임은 빈 칸 양식이나 학급별 인원 집계로 만든다. 원고에 개인정보가 있으면 빼고 만든 뒤 뺐다고 알린다.
4. **공문 원문을 옮겨 적지 않는다.** 근거는 기관·문서번호·날짜·제목만 쓴다.
5. **한글 파일은 직접 열어 확인한다.** 패키지 검사를 통과해도 실제 한글에서 열어 본 것은 아니다. 렌더로 쪽을 확인하고, 마지막에 선생님께 한글에서 열어 쪽 나눔을 확인해 달라고 말한다. "완벽하다", "바로 결재 올리면 된다"고 말하지 않는다.
6. **계획안은 승인이 아니다.** 예산은 "예상액", 일정은 "예정"으로 쓴다. 결재·발송·정산은 선생님이 따로 한다.

## 0. 준비

Python 3와 패키지 두 개(lxml, python-hwpx)가 필요하다. `school-start`(시작하기)를 마쳤으면 건너뛴다. 스크립트가 시작하기가 만든 `~/.chilseo/venv`를 알아서 찾아 쓴다.

패키지가 없으면 스크립트가 한국어로 알려 주고 멈춘다. 그때는 둘 중 하나를 한다.

- Claude Code: `school-start` 스킬로 준비한다(`~/.chilseo/venv`에 설치).
- 그 밖의 환경: `python3 -m pip install -r "$S/requirements.txt"`. `externally-managed-environment`로 막히면 `python3 -m venv .venv`를 만들고 그 안의 pip(`.venv/bin/pip`, Windows는 `.venv\Scripts\pip.exe`)로 설치한 뒤, 아래 모든 `python3`를 그 venv의 python으로 바꿔 실행한다. Windows에서 `python3`가 없으면 `python` 또는 `py -3`을 쓴다.

kordoc 도구(`render_document`, `parse_document`, `patch_document`)가 연결되어 있으면 렌더 확인과 수정본 고치기에 쓴다. 없어도 생성과 검사는 된다.

## 1. 처음 쓸 때 확인 (한 번만)

작업 폴더에 `학교설정.json`이 있으면 읽고 넘어간다. 없으면 `~/.chilseo/학교설정.json`을 본다. 둘 다 없으면 아래를 **한 번에** 묻는다.

1. 학교 이름 (예: 칠서초등학교)
2. 학교 양식
   - 칠서초등학교 → 기본 양식을 쓴다.
   - 다른 학교 → 예전에 결재한 계획서 HWPX 하나를 받는다. 머리말(학교 표어·제목 상자·교표)이 문서 맨 앞에 있어야 한다. `clean_template.py`로 빈 양식을 만든다(아래 "다른 학교 양식 만들기").
3. 원고가 어디 있는지: 노션 페이지 주소, 대화에 붙여 넣은 글, 파일, 작년 계획서 중 하나

답을 받으면 작업 폴더의 `학교설정.json`에 저장해서 다음에는 묻지 않는다. 이 스킬이 쓰는 칸은 `school`과 `template`이다. 파일이 이미 있으면 이 두 칸만 채우고, 다른 스킬이 쓰는 칸(결재선·전화 등)은 지우지 않는다.

```json
{"school": "칠서초등학교", "template": "chilseo_plan_template.hwpx"}
```

Claude 앱처럼 파일이 남지 않는 곳에서는 "프로젝트 지침에 학교 이름과 양식을 적어 두면 다음에 다시 묻지 않는다"고 안내한다.

## 2. 원고 읽기

- 노션 주소를 받으면 노션 커넥터로 본문과 속성을 읽는다. 커넥터가 없으면 연결 방법을 안내하거나 본문을 붙여 넣어 달라고 한다.
- 작년 계획서 파일(HWPX·HWP·PDF)을 받으면 그것을 원고로 삼아 올해 계획서를 만든다. kordoc `parse_document`로 읽고, 절·항목 짜임과 문장은 살린다. 해마다 바뀌는 값(날짜·요일·대상·인원·예산·근거 공문·담당)은 작년 값을 옮기지 않고 한 번에 모아 묻는다. 작년 문서번호는 넣지 않는다. 다 만든 뒤 작년과 달라진 곳을 짧게 알려 준다.
- 원고에서 제목, 근거, 목적, 방침, 세부 운영(기간·대상·장소·담당), 시간표, 예산 항목, 기대 효과를 찾는다.
- 노션 글머리(❍ ○ • - * ###)는 문서마다 다르다. 기호 모양으로 단계를 정하지 않고 바깥 절 기준 깊이로 정한다. 정규화는 `scripts/hierarchy.py`를 참고한다.

학교 표준 단계와 입력 JSON의 `kind`:

```
1단  1.   절 제목     → heading     (14pt 굵게)
2단  가.  항목        → text        (11pt)
3단  1)   세부 항목   → text        (11pt)
4단  -    덧붙임·※    → note        (10pt)
     소제목이 따로 필요할 때 → subheading (12pt)
```

로마숫자 절(Ⅰ Ⅱ)은 `1. 2. 3.`으로 다시 번호를 단다. `1) 2026. 4. ~`의 `2026.`을 글머리로 읽지 않는다(숫자 글머리는 두 자리까지만).

## 3. 입력 JSON 쓰기

형식은 `references/input-format.md`, 예시는 `examples/sample_reading_week.json`이다.
JSON이 생성의 원본이다. 선생님께는 JSON 대신 내용을 사람이 읽는 글로 짧게 보여 주고, 모자란 값을 함께 묻는다.

## 4. 만들기와 검사

```bash
python3 "$S/scripts/build.py" 계획.json -o 결과/계획서.hwpx
```

- 같은 이름으로 `.validation.json`(검사 결과)과 `.txt`(본문 글자)가 함께 생긴다.
- 만들기 전에 JSON을 검사한다: 학교 이름이 양식 머리말과 같은지, 예산 산출식(곱셈)과 항목 합계, 표에 적힌 금액과 산출식이 JSON과 같은지, 시간표의 학급 중복, 표 칸 수, 열 정렬 값.
- 만든 뒤 파일을 검사한다(`scripts/gate.py`). 하나라도 ⛔이면 파일을 넘기지 않는다.

| 검사 | 내용 | 막음 |
|---|---|---|
| open | ZIP·XML·그림·글자 모양 참조가 맞고 다시 열리는지 | ✔ |
| residue | `{{변수}}` `TODO` `○○○` 같은 자리표시자가 남았는지 | ✔ |
| budget | 예산표 합계 = 항목 합 | ✔ |
| weekday | `2026. 12. 8.(화)`의 요일이 달력과 맞는지 | ✔ |
| attend | 출석부 열 수 = 3 + 운영일수 + 2 | ✔ |
| concat | 문단 중간에 글머리가 끼어 원문이 덧붙었는지 | ✔ |
| secnum | 절 번호가 이어지는지 | 알림 |
| empty | 필수 절(근거·목적·예산)이 있는지 | ✔ |

자리표시자 검사는 정상 문서를 막지 않는 쪽을 우선한다. 서명란 `______`, 시간표의 `N/A`, 붙임의 `— 예시` 라벨은 정상으로 본다.
검사에 걸리면 JSON을 고쳐 다시 만든다. 못 고치면 이유를 말하고 파일을 넘기지 않는다.

## 5. 눈으로 확인

1. kordoc `render_document`가 있으면 모든 쪽을 렌더해 잘림·겹침·빈 쪽·표 넘침을 본다. 렌더는 한글 실제 조판의 근사다.
2. 결과를 넘길 때 함께 말한다: 무엇을 넣었는지, 무엇을 "미정"으로 두었는지, 뺀 개인정보가 있는지, 검사 결과.
3. "한글에서 열어 쪽 나눔을 확인하고, 필요하면 PDF로 저장해 주세요"라고 안내한다.

## 6. 선생님이 한글에서 고친 파일을 다시 줄 때

- 그 파일이 새 원본이다. JSON으로 다시 만들지 않는다. 다시 만들면 선생님이 고친 서식(빈 줄·들여쓰기·글자 모양·표 선)이 사라진다.
- kordoc `parse_document(keep_layout_tables: true)`로 읽고 `patch_document`로 필요한 곳만 고쳐 새 이름으로 저장한다. 원본은 덮어쓰지 않는다.
- 표에 행을 끼우면 첫 본문 행의 선 모양이 복제될 수 있다. 렌더로 확인한다.

## 다른 학교 양식 만들기

```bash
python3 "$S/scripts/clean_template.py" 예전계획서.hwpx -o 우리학교_계획서_양식.hwpx
```

- 머리말(문서 맨 앞 세 문단)을 남기고, 본문 문단 하나와 표 하나를 서식 견본으로 남긴다. 나머지 본문·두 번째 구역·미리보기 그림·쓰지 않는 그림·작성자 정보를 지우고 남은 글자도 비운다.
- 견본을 직접 고르려면 `--para 번호 --table 번호`(section0의 문단 순서, 0부터)를 준다.
- 만든 양식을 렌더해 머리말과 교표가 남았는지, 예전 계획서 내용이 없는지 선생님과 함께 확인한다.
- 칠서초 양식 외에는 시험 단계다. 처음 몇 번은 결과를 한글에서 꼭 열어 본다.

## 표 모양

본문 표는 파란 선 양식으로 만든다. 선 색 `#6182D6`, 머리행 바탕 `#DFE6F7`, 머리행 아래 얇은 이중선, 바깥 세로선은 조금 굵게, 본문 10pt·줄 간격 130%·세로 가운데.
가로 정렬은 열마다 `align`으로 정한다(center·justify·left·right). 칸 안 줄 바꿈은 `\n`을 쓴다. 제목의 `\n`은 한글 줄 바꿈이 된다.

## 지원 범위

- 검증한 것: 칠서초 내부결재용 계획서 양식.
- 학운위 심의용·교육청 제출용 양식, 첨부가 PDF뿐인 계획서, 규정문은 대상이 아니다. 그렇다고 알린다.
- PDF는 한글에서 저장한다. 한글 없이 PDF를 만드는 기능은 없다.
