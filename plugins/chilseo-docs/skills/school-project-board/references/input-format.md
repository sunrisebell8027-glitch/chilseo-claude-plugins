# 보드 JSON 형식

예시(모두 지어낸 자료). 날짜는 모두 `YYYY-MM-DD`로 쓴다.

- 작업형 프로젝트: `examples/sample_video_shoot_board.json` (학교·결재·예산 없음, 할 일마다 자료)
- 학교 사업: `examples/sample_science_club_board.json` (길잡이·기안문·예산 장부)

`project`, `updated`는 꼭 넣는다. 목록 칸(`docs`, `decide`, `schedule`, `log`, `ledger`)은 생략하면 빈 목록으로 처리한다. 형식이 틀리거나 허용하지 않는 값을 넣으면 빌더가 고칠 칸을 한국어로 알려 준다.

## 선택 기능: 결재 문서와 예산

기본 보드는 정할 것 · 할 일 흐름 · 일정 · 작업 기록이다. 아래 두 기능은 **자료가 있을 때만** 켜진다(기본은 빼기). 꺼져 있으면 그 칸, 그 검사, 그 말(결재·기안문·편성액·품의)이 모두 빠지고 남은 칸이 빈자리 없이 채운다.

| 기능 | 켜지는 때 | 켜지면 더해지는 것 |
|---|---|---|
| 결재 문서 (`approval`) | `guide`가 있거나, 할 일 하나라도 `draft`·`doc_no`·`need`가 있을 때 | 길잡이 칸, "문서 흐름"·"결재 문서" 이름, 상태 이름 결재 완료·결재 중·작성 중, 기안문 종이, 문서번호 검사, 늘 보이는 검사 칸 |
| 예산 (`budget`) | `ledger`·`amounts`·`budget_code`가 있거나, 길잡이에서 예산을 쓴다고 답했을 때(`"budget": "yes"`) | 남은 돈·예산 장부 칸, 품의(할 일)와 장부 합계 검사, 편성액 검사 |

- 자료 없이 미리 켜려면 맨 위에 `"approval": true`나 `"budget": true`를 쓴다.
- `false`로 끄면서 그 기능의 자료를 함께 넣으면 오류다(자료가 보이지 않게 숨는 일을 막는다). 자료를 지우거나 칸을 뺀다.
- 결재 문서를 켜지 않고 예산만 켜면 화면 말은 "예산 · 쓴 돈 · 쓸 돈"이 되고, 품의 금액(`amounts`)을 따로 적지 않아도 된다(장부 줄의 `doc`이 할 일 id인지만 본다).

## 맨 위

| 칸 | 꼭 | 내용 |
|---|---|---|
| `project` | ✔ | 프로젝트(사업) 이름. 부탁 문구의 「」 안에 들어간다 |
| `updated` | ✔ | 마지막으로 고친 날. 지난 기한과 일정의 남은 날을 이 날 기준으로 센다 |
| `school` | | 학교 이름. 있으면 머리줄에 "프로젝트 보드 · 학교 이름"으로 보인다. 기안문(`draft`)을 넣으면 꼭 있어야 한다 |
| `period` | | `[시작, 끝]` |
| `owner` | | "담당 교사"처럼 쓴다. 실명은 넣지 않는다 |
| `approval` | | `true`·`false`. 결재 문서 기능을 직접 켜고 끈다. 없으면 자료로 정한다 |
| `budget` | | `true`·`false`. 예산 기능을 직접 켜고 끈다. 없으면 자료로 정한다 |
| `budget_code` | | 예산과목(에듀파인에서 본 그대로). 넣으면 예산 기능이 켜진다 |
| `example` | | `true`면 "예시 자료" 표시 |
| `look` | | `"blueprint"`면 청사진 모양 |
| `page_title` | | 브라우저 탭 이름. 없으면 "프로젝트 이름 보드" |

`look`은 생략하거나 `blueprint`를 쓴다. `example`, `approval`, `budget`은 생략하거나 참·거짓 값으로 쓴다.

## `docs`: 할 일 흐름

결재 문서 보드에서는 문서, 작업형 보드에서는 할 일이다. 같은 칸을 쓴다.

| 칸 | 꼭 | 내용 |
|---|---|---|
| `id` | ✔ | 영문 id. 할 일마다 달라야 한다 |
| `title` | ✔ | 할 일(문서) 제목 |
| `status` | ✔ | 아래 상태 표 |
| `kind` | | 실습 영상·대본·계획·품의처럼 짧은 종류 |
| `group` | | 묶음 이름(예: "준비", "촬영", "마무리"). 모든 할 일에 붙이거나 모두 뺀다 |
| `due` | | 기한. 지났는데 마치지 않았으면 확인 표시 |
| `date` | | 마친 날(결재 문서는 결재한 날) |
| `note` | | 짧은 설명·메모. 줄바꿈을 그대로 보여 준다 |
| `links` | | 자료 링크 `[{"label": "② 대본", "url": "https://…"}]`. 영상이면 `"type": "video"` |
| `checklist` | | 할 것 목록 `[{"text": "알림 끄기", "done": true}, "새로 고치기"]`. 글자만 쓰면 `done: false` |
| `images` | | 시안 미리보기 `[{"src": "시안/첫장면.png", "alt": "첫 장면 시안"}]`. png·jpg, 한 장 1.5MB 이하, 보드 JSON 폴더 기준 |
| `doc_no` | | 문서번호(결재 문서). `done`이면 있어야 한다(없으면 확인 표시). 넣으면 결재 문서 기능이 켜진다 |
| `need` | | 길잡이 문서 id: `plan` · `newmoney` · `safety` · `letter` · `buy` · `report` |
| `phase` | | `need`가 없는 문서의 단계: `prep` · `notice` · `run` · `close`(없으면 `run`). 길잡이 없는 보드에서 `group` 대신 쓰면 준비·안내·진행·마무리로 묶는다 |
| `draft` | | 기안문. `school-gongmun-draft`의 입력과 같은 형식(`receiver`, `via`, `written`, `related`, `lead`, `items`, `attachments`) |

### 상태

| 값 | 작업형 보드 | 결재 문서 보드 |
|---|---|---|
| `todo` | 아직 | 아직 |
| `doing` | 하는 중 | 작성 중 |
| `draft` | 하는 중 | 작성 중 |
| `review` | 확인 중 | 결재 중 |
| `done` | 마침 | 결재 완료 |

`doing`과 `draft`는 같은 상태다. 작업형 보드는 `doing`, 결재 문서 보드는 `draft`로 쓰면 읽기 쉽다.

### 지금 할 일과 다음 할 일

- 길잡이가 있으면 길잡이 차례(필요한 문서를 단계 순서로)에서 고른다.
- 길잡이가 없으면 할 일 흐름에서 고른다. **하는 중**인 할 일을 먼저, 그다음 **아직** 시작하지 않은 할 일, **확인 중**인 할 일은 맨 뒤다. 같은 상태끼리는 흐름 순서를 따른다. 화면에는 "지금 할 일"·"다음" 표시가 붙고, 넓은 화면에서는 지금 할 일을 펼쳐 둔다.
- 흐름 순서는 적은 순서다. `phase`나 `need`를 쓰면 단계 순서(준비 → 안내 → 진행 → 마무리)로 놓고, 같은 단계 안에서는 적은 순서를 지킨다.

### 자료가 없는 할 일

`note`·`links`·`checklist`·`images`가 모두 없는 할 일을 누르면 "자료를 붙이면 여기에서 바로 열 수 있어요"와 Claude에게 보낼 부탁 문구를 보여 준다(결재 문서 보드는 지금처럼 기안문 안내를 보여 준다).

> 「{project}」 보드의 ‘{title}’에 필요한 자료를 붙여 주세요. 이미 있는 자료는 링크로 넣고, 없는 자료는 만들어서 넣어 주세요.

## `guide`: 길잡이 답 (결재 문서 보드)

질문 id를 키로, 고른 답의 값을 적는다. 질문과 답 값은 `scripts/guide.py`의 `QUESTIONS`에 있다.

```json
"guide": {"lastyear": "yes", "budget": "yes", "source": "school", "outside": "yes", "consent": "reply", "external": "no", "report": "no"}
```

답하지 않은 질문은 빼 둔다. 그 질문에 걸린 문서는 "답 기다림"으로 흐리게 보인다. 예산 질문에 답하지 않았으면 예산 칸은 아직 보이지 않는다.

품의(`buy`)는 돈을 쓸 때마다 한 건씩 넣는다. 모두 `done`이어야 차례에서 마친 것이 된다.

## `ledger`, `amounts`: 예산 장부 (예산 기능)

```json
"ledger": [{"name": "실험 재료비", "allocated": 200000, "spend": [{"doc": "buy2", "name": "리트머스 종이·비커 세트", "amount": 156000}]}],
"amounts": {"buy1": 180000}
```

- `spend.doc`은 그 돈을 쓰는 품의(할 일) id다. 그 할 일이 `done`이면 집행(쓴 돈), 아니면 결재 전(쓸 돈)으로 센다.
- 결재 문서 보드에서 품의 금액은 기안문의 소요예산에서 읽는다. 기안문이 없는 품의는 `amounts`에 적는다. 품의 금액과 장부 줄의 합이 다르면 화면을 만들지 않는다.
- `allocated`, `spend.amount`, `amounts` 금액은 0 이상의 정수로 쓴다. 장부 줄에서 `spend`를 생략하면 빈 목록으로 처리한다.
- 각 금액과 장부의 편성액 합계·집행 합계는 각각 9,007,199,254,740,991원 이하여야 한다. 화면에서 금액이 바뀌지 않도록 정한 한도다.

## 나머지

- `decide`: 정할 것. `[{"text": "…", "doc": "할 일 id"}]`(`doc`은 없어도 된다. 있으면 카드에 "관련 할 일 보기"가 붙는다)
  - `images`: 무엇을 보고 정하는지 보여 주는 캡처. `[{"src": "캡처/심사기준.png", "alt": "붙임 1 심사 기준"}]`. 경로는 보드 JSON이 있는 폴더 기준이고 png·jpg, 한 장 1.5MB 이하. 보드 파일 안에 넣어 두고, 누르면 크게 뜬다. 학생·교직원 이름이 보이는 캡처는 넣지 않는다.
  - `links`: 원문 링크. `[{"label": "공문 본문", "url": "https://…"}]`. 화면에는 "공문 본문 열기"로 보인다.
- `schedule`: `[{"date": "…", "title": "…"}]`
- `log`: 작업 기록. `[{"date": "…", "text": "…"}]` 최근 4개를 보여 준다
- 검사 칸: 결재 문서 보드는 늘 보인다. 작업형 보드는 확인할 것(지난 기한, `[확인 필요]`)이 있을 때만 보인다.
