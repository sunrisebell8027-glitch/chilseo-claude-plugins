# KRDS 디자인 (대한민국 정부 디자인 시스템)

KRDS는 행정안전부가 만든 디지털 정부 서비스 공식 디자인 시스템이다. 누구나 같은 노력으로 서비스를 쓸 수 있게 하는 것(디지털 포용)과 웹 접근성을 중심에 둔다. 학교에서 보호자와 학생 모두가 쓰는 화면에 잘 맞는다.

KRDS 자료는 **출처를 표시하면 별도 허락 없이 쓸 수 있다**(KRDS 저작권 정책, 저작권법 제24조의2). 출처 표기 방법은 아래 6단계에 있다.

## toss-design 스킬과 고르기

한 앱에는 시각 스타일 기준을 하나만 쓴다.

| 이런 화면이면 | 이 스킬을 기준으로 |
|---|---|
| 수업 활동, 게임, 타이머, 모둠 배정처럼 학생이 즐겁게 쓰는 도구 | toss-design |
| 가정통신문, 신청·동의, 설문, 공지, 학교 행정 업무처럼 문서·서식 성격의 화면 | **krds-design** |
| 둘이 섞여 있으면 | 사용자에게 어느 쪽이 중심인지 묻고 하나를 고른다 |

KRDS를 고르더라도 다음은 함께 쓴다.
- toss-design의 **A. 흐름 설계**(문제 다시 정의, 행동 단위로 쪼개기, 화면 지도)
- toss-writing의 **핵심 철학, 문구 규칙, 다크패턴 점검**. KRDS 화면도 문구는 해요체로 쓴다. 공문서체("~합니다")가 필요한 서식이라면 사용자에게 확인한다.
- web-assets의 **자료 받기**와 **출처 정리**

## 1단계: KRDS 디자인 원칙 7가지로 판단한다

설계하며 막힐 때 이 원칙으로 판단한다.

1. **사용자 중심**: 만드는 사람 편의가 아니라 쓰는 사람의 필요에서 시작한다.
2. **모든 사용자 포용**: 장애인, 고령자, 어린이, 외국인 가정도 같은 노력으로 쓸 수 있어야 한다.
3. **공통된 경험 안에서 개별 특성 고려**: 익숙한 표준 모양을 쓰되, 이 서비스만의 필요는 채운다.
4. **빠르고 간단하게**: 단계와 입력을 줄인다. 이미 아는 정보를 다시 묻지 않는다.
5. **쉽게 이해하고 사용**: 쉬운 말, 예측 가능한 동작.
6. **다양한 상황 고려**: 작은 화면, 느린 인터넷, 급한 상황, 처음 쓰는 사람.
7. **신뢰**: 무엇을 왜 묻는지, 정보가 어디에 저장되는지 분명히 알린다.

## 2단계: 화면 유형에 맞는 패턴을 고른다

KRDS는 자주 쓰는 화면 흐름을 "패턴"으로 정리해 두었다. 학교 화면에 이렇게 대응한다.

| 학교 화면 | KRDS 패턴 | 핵심 |
|---|---|---|
| 체험학습 신청서, 방과후 신청 | 서비스 패턴 > 신청 / 기본 패턴 > 입력 폼 | 단계 표시(step indicator)로 지금 몇 단계인지 보여 주고, 마지막에 확인 화면을 둔다 |
| 개인정보 수집·이용 동의서 | 기본 패턴 > 동의 | 필수와 선택 동의를 나누고, 무엇을 왜 얼마 동안 보관하는지 쓴다. 전체 동의 하나로 묶어 강요하지 않는다 |
| 학생·보호자 정보 입력 | 기본 패턴 > 개인 식별 정보 입력 | 꼭 필요한 정보만 묻는다. 입력 형식(예: 휴대전화 번호)을 미리 보여 준다 |
| 가정통신문, 공지 목록 | 기본 패턴 > 목록 탐색, 필터링·정렬 | 최신순, 날짜·담당 표시, 검색 |
| 가정통신문 본문 | 기본 패턴 > 상세 정보 확인, 첨부파일 | 요약을 맨 위에, 첨부파일 이름·형식·크기 표시 |
| 제출 완료·오류 | 기본 패턴 > 확인, 오류, 사용자 피드백 | 무엇이 완료됐는지, 오류는 어디를 어떻게 고치면 되는지 |
| 설문 | 기본 패턴 > 입력 폼, 사용자 피드백 | 한 화면에 질문 몇 개만, 진행률 표시 |

패턴의 자세한 규칙은 KRDS 누리집(https://www.krds.go.kr)의 "기본 패턴", "서비스 패턴" 메뉴에서 확인한다.

## 3단계: 스타일 기준

KRDS 디자인 토큰(CSS 변수)을 쓰면 색·글자·간격이 자동으로 KRDS 기준을 따른다.

- **글꼴**: Pretendard GOV
- **글자 크기**(PC 기준): 본문 17px, 큰 본문 19px, 작은 본문 15px. 제목은 17~40px 단계, 큰 표제는 36~60px.
- **색**: 주 색(primary) 파랑 계열 `--krds-color-light-primary-50`(#256ef4) 등. 상태 색(성공·주의·위험·정보)이 따로 있다. 색 이름을 직접 쓰지 말고 토큰을 쓴다.
- **선명한 화면 모드**: KRDS는 고대비 색 토큰(`high-contrast`)을 함께 제공한다. 저시력 사용자를 위한 화면 모드를 넣을 수 있다.
- **글자·화면 크기 설정**: 사용자가 글자 크기를 단계별로 키울 수 있게 하는 것이 KRDS 누리집의 기본 기능이다. 보호자용 화면에는 넣는 것을 권한다.

## 4단계: 만드는 방법을 고른다

| 방법 | 언제 | 하는 일 |
|---|---|---|
| ① 원칙만 따르기 | 직접 쓴 CSS나 다른 스타일로 만들 때 | 1~2단계 원칙과 패턴만 적용 |
| ② 컴포넌트 키트 쓰기 | KRDS 모양 그대로 빠르게 만들 때 | 아래 순서대로 |

②를 고르면:

1. 자료 받기 (web-assets 스킬의 스크립트):
   ```bash
   python3 "${CLAUDE_SKILL_DIR}/../web-assets/scripts/fetch_assets.py" <프로젝트 폴더> --krds
   ```
   web-assets 스킬이 같은 묶음에 없으면(Claude 앱에 따로 올린 경우 등) web-assets 스킬 폴더의 `scripts/fetch_assets.py`를 찾아 쓴다.
   KRDS CSS·JS, 아이콘, Pretendard GOV 글꼴을 받고, CSS 안의 아이콘 주소를 로컬 경로로 바꾼다. 원래 CSS는 krds.go.kr 서버의 아이콘을 불러오기 때문에 그대로 쓰면 인터넷이 없을 때 아이콘이 사라진다.
2. HTML에 연결:
   ```html
   <link rel="stylesheet" href="assets/vendor/pretendard-gov/font.css">
   <link rel="stylesheet" href="assets/vendor/krds/krds.min.css">
   ...
   <script src="assets/vendor/krds/krds.min.js"></script>  <!-- </body> 바로 앞 -->
   ```
3. 컴포넌트 HTML은 공식 예제를 받아 고쳐 쓴다. 이름과 주소는 `references/components.md`에 있다. 예:
   ```html
   <button type="button" class="krds-btn primary">신청하기</button>
   ```

주의할 점:
- KRDS CSS는 `html { font-size: 62.5% }`로 1rem을 10px로 바꾼다. 직접 쓰는 CSS도 이 기준(1.7rem = 17px)으로 쓰고, Pico 같은 다른 CSS와 섞지 않는다.
- CSS 590KB, JS 190KB 정도다. 컴포넌트 몇 개만 쓴다면 ①번 방법이 가볍다.
- 예제의 자리표시 글자("버튼 : primary", "단계 레이블", "모달 제목")를 그대로 남기지 않는다.

## 5단계: 쓰면 안 되는 것

KRDS에는 정부 누리집임을 나타내는 요소가 있다. 학교 앱이 정부 공식 서비스로 오인되면 안 되므로 다음은 쓰지 않는다.

- **공식 배너(masthead)**: "이 누리집은 대한민국 공식 전자정부 누리집입니다" 문구
- **운영기관 식별자(identifier)**와 정부 상징(태극 문양), 정부 기관 로고·파비콘
- 실제 정부 누리집처럼 보이게 하는 머리글·바닥글 구성(예: 정부 대표 전화, 행정안전부 표기를 운영 주체처럼 쓰기)

머리글·바닥글이 필요하면 KRDS 컴포넌트 구조만 빌리고, 학교·교사 이름과 앱 이름을 넣는다.

## 6단계: 출처 표시와 마무리 점검

KRDS 자료(컴포넌트 키트, 아이콘, 토큰)를 쓰면 출처를 표시한다. web-assets 스크립트가 `THIRD_PARTY_NOTICES.md`에 아래 내용을 자동으로 적는다. 공모전 사용 방법 안내 PDF나 README에도 옮겨 적는다.

> 이 앱은 행정안전부 「KRDS - Korea Design System」(https://www.krds.go.kr)의 디자인 시스템을 이용했어요.

점검:
- [ ] 정부 공식 배너, 식별자, 정부 상징을 쓰지 않았는가?
- [ ] 예제 자리표시 글자가 남아 있지 않은가?
- [ ] 단계가 있는 서식에 단계 표시와 마지막 확인 화면이 있는가?
- [ ] 동의 화면에서 필수·선택을 나누고, 수집 항목·목적·보관 기간을 썼는가?
- [ ] 글자 크기를 키워도 화면이 깨지지 않는가? (브라우저 확대 200%로 확인)
- [ ] 키보드만으로 모든 칸을 채우고 제출할 수 있는가?
- [ ] 인터넷을 끄고 열어도 아이콘·글꼴이 보이는가?
- [ ] 출처 표시를 `THIRD_PARTY_NOTICES.md`와 안내 문서에 넣었는가?

컴포넌트 예제 목록은 `references/components.md`, 근거 자료는 `references/sources.md`에 있다.
